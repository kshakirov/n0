# #3 — Собираю потоковый парсер chunked-тела по модели nuXmv

## Точка остановки — 2026-11-03

Довёл автомат chunked-тела по модели: один и два HTTP-чанка проходят, разрывы сетевых порций внутри данных и CRLF тоже проходят со свежими аренами. Fixed не сломал. Обновил NAPI под новые состояния и сохранение delimiter_context; отдельно проверил продолжение chunked-тела из Node.

До готового сквозного запроса остался заголовок: распознавание имени Transfer-Encoding ещё надо довести, а значение chunked пока вообще не разбираю. Следующим шагом распознаю именно chunked в значении и только после этого выбираю соответствующий автомат. Затем прогоню полный POST через Rust и Node. Текущий тест заголовка с ожиданием NoContent — промежуточный, его тоже обновлю.

Я переношу в Rust автомат chunked-тела по обкатанной модели `nuxmv/body_parse_automaton_ver_5.smv`: модель проверялась на Python, полный вариант уже реализован на Java.

Читаю hex-размер чанка, пропускаю служебные CRLF и выдаю в арену только полезные байты. Состояние автомата сохраняю между сетевыми порциями отдельно от общей фазы запроса; арену создаю заново на каждый вызов и сразу отдаю заполненную часть обработчику.

Уже набросал состояния и чтение размера. В runner добавил самый простой пример `3\r\nabc\r\n0\r\n\r\n` → `abc`; пока он падает на недописанных переходах.

Дальше доведу переходы по модели, подключу выбор chunked после заголовков и обновлю передачу состояния через NAPI. Проверю один и несколько чанков, разрывы сетевых порций внутри размера, данных и CRLF, нулевой чанк и ошибочные разделители. Минимальный проход — без расширений чанков и трейлеров.

Считаю готовым, когда из Node и чистого Rust получаю одинаковые порции тела без служебной разметки, а завершение происходит после полного нулевого чанка и финального CRLF.

## Точка остановки — 2026-10-29

Набросал состояния chunked-автомата, чтение hex-размера, данных и CRLF по модели nuXmv. Развёл ReadFixedData и ReadChunkData; fixed в runner снова проходит.

Остановился на первом чанке `3\r\nabc\r\n0\r\n\r\n`: после размера на LF получаю Error, потому что delimiter_context ещё остаётся NoDelimiter. Дальше выставлю AfterSize / AfterZero при завершении размера и AfterData после данных, затем проверю оставшиеся переходы и нулевой чанк.

Ещё обновлю NAPI: после добавления delimiter_context addon пока не собирается — поле отсутствует в инициализаторе. Надо передавать и сохранять его вместе с состоянием тела и сверить числовые коды enum. После одиночного чанка проверю несколько чанков и разрывы между сетевыми порциями.
