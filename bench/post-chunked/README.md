# POST chunked: подготовленный стенд

Одна команда для сборки и последовательного сравнения обоих серверов:

```sh
cd /home/kshakirov/repos/n0-post-chunked
bash bench/post-chunked/run-all.sh
```

Скрипт собирает release-addon, запускает N0 на 10 секунд, останавливает его, ждёт 65 секунд и запускает node:http на 10 секунд. В конце выводит показатели обоих вариантов и путь к полным результатам. При прерывании текущий тестовый сервер останавливается. Занятый порт не освобождает принудительно. Это предварительное сравнение, не серия повторов с прогревом.

Тело 256 КиБ, 256 HTTP-чанков по 1024 байта; размер каждого в wire-формате — `400` hex. Один POST на соединение, `Connection: close`. Один и тот же сырой запрос wrk отправляет обоим серверам, без автоматического переформатирования чанков клиентской HTTP-библиотекой. TCP вправе объединять и дробить эти HTTP-чанки.

Оба обработчика считают полезные байты без накопления тела, отвечают `OK` после завершения и проверяют размер 262144 байта. N0 получает свежую арену на каждую сетевую порцию. Результат — сравнение текущих реализаций, включая стоимость этих арен. Путь распознавания значения `chunked` пока не завершён; запрос содержит ровно поддерживаемый вариант заголовка.

Сборка: `cargo build --release -p addon`, затем копирование `target/release/libn0.so` в `target/release/n0.node`.

Запускать только после согласования, строго по одному:

```sh
bash bench/post-chunked/run.sh n0
bash bench/post-chunked/run.sh node-http
```

Начальный профиль: два потока wrk, 10 соединений, 10 секунд, localhost:18083. Это закрытая нагрузка с одинаковой конкуренцией, не заданный RPS. Скрипт сохраняет результат и сведения о версии в `bench/var/post-chunked/`. Для итогового сравнения нужны одинаковый прогрев, несколько чередующихся повторов и пауза на освобождение TCP-портов; одиночный запуск только предварительный. Профилирование аллокаций — отдельным проходом, не одновременно с измерением скорости.
